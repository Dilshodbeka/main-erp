# Мастер начальной настройки (Setup Wizard)

**Дата:** 2026-11-11
**Статус:** дизайн одобрен владельцем в диалоге 2026-11-11; документ фиксирует согласованное решение
**Реализация:** не начата; живые SQL-изменения и deploy не входят в этот документ

## 1. Цель и границы

После первого создания компании в облаке владелец видит пустую систему: без работников, материалов, операций и заказов большинство экранов пусты, а первые действия требуют знания последовательности. Мастер из четырёх шагов проводит владельца по минимальному рабочему набору и на каждом шаге предлагает два пути: **«Qo‘lda kiritish»** — открыть существующий экран или модалку, либо **«Demodan olish»** — загрузить образец данных прямо в текущую компанию.

Первая версия включает:

- модальный мастер, который автоматически открывается после создания компании;
- повторный запуск из «Sozlamalar → Ma’lumotnoma» (только облачный режим, только администратор);
- 4 шага: Xodimlar, Materiallar, Operatsiyalar, Birinchi buyurtma;
- индикатор прогресса «n / 4 qadam tayyor» и бейдж «Tayyor» на выполненном шаге;
- демо-загрузку, идемпотентную по именам: повторный запуск не создаёт дубликатов;
- самодостаточность шага: «Demodan olish» на любом шаге сам создаёт недостающие предпосылки (шаг заказа создаёт и людей, и материалы, и операции, если их нет);
- онлайн-проверку для облачного режима: демо — только при наличии сети.

Первая версия **не** включает:

- удаление или сброс демо-данных (для этого уже есть модульный reset и очистка локалной демо-базы);
- демо-шаблоны маршрутов;
- запуск демо-заказа в производство;
- мастер в демо-режиме приложения — там вся база уже демонстрационная;
- новые команды, таблицы или изменения схемы: используются только существующие `employee.create`, `item.create`, `operation.create`, `customer.create`, `order.create`.

## 2. Поток

1. Владелец впервые входит в облако. `load()` получает ответ «not been linked» и показывает экран `CompanyOnboarding`.
2. После успешного `bootstrapCompany` приложение открывает мастер поверх рабочего экрана (`modal = setup`).
3. Мастер показывает четыре шага. У каждого — название, описание и проверка выполнения по текущему состоянию. Если шаг не выполнен, доступны кнопки «Qo‘lda kiritish» и «Demodan olish»; если выполнен — бейдж «Tayyor».
4. «Qo‘lda kiritish» закрывает мастер и открывает существующий экран:
   - Xodimlar → модалка «Yangi xodim»;
   - Materiallar → модалка «Katalogga material»;
   - Operatsiyalar → раздел «Sozlamalar → Ma’lumotnoma»;
   - Birinchi buyurtma → модалка нового заказа.
5. «Demodan olish» последовательно выполняет команды через `execute()` и после завершения обновляет прогресс. На время загрузки все кнопки шага блокируются, на активной кнопке — «Yuklanmoqda…». Уведомление сообщает число добавленных записей или что демо уже загружено.
6. Закрытие — кнопка «Yopish» или Escape. Мастер ничего не блокирует: его можно открыть снова из Sozlamalar.
7. Повторный вход: «Sozlamalar → Ma’lumotnoma» показывает карточку «Boshlang‘ich sozlash» с кнопкой «Sozlashni ochish» (только облако и администратор).
8. Офлайн в облаке: кнопки «Demodan olish» отключены с пояснением; «Qo‘lda kiritish» работают как обычно через существующую офлайн-очередь.

## 3. Компоненты

### 3.1 `src/setup.ts` — чистая логика

```ts
export type SetupStepId = 'employees' | 'materials' | 'operations' | 'order';

export interface SetupStep {
  id: SetupStepId;
  title: string;
  description: string;
  done: (state: State) => boolean;
}

export const setupSteps: SetupStep[];

export function nextDemoCommand(step: SetupStepId, state: State): Command | null;
```

Правила:

- `done`:
  - `employees` — есть хотя бы один активный работник;
  - `materials` — есть хотя бы один собственный материал (`customerId === null`);
  - `operations` — есть хотя бы одна активная операция;
  - `order` — есть хотя бы один заказ.
- `nextDemoCommand` возвращает следующую недостающую команду или `null`, если демо шага завершено.
- Команды строятся лениво: каждая следующая зависит от результата предыдущей (`??`-цепочка), ID материалов и операций читаются из уже применённого состояния.
- Сравнение имён — без учёта регистра и внешних пробелов, как `named()` в домене.
- Шаг «operations» перед операциями создаёт недостающих людей и материалы; шаг «order» — людей, материалы, операции и клиента. Шаги «employees» и «materials» самодостаточны без предпосылок.

### 3.2 `src/components/SetupWizard.tsx`

  busy: boolean;
  online: boolean;
  close: () => void;
  runDemo: (step: SetupStepId) => Promise<boolean>;

Рендер: `Dialog` с заголовком «Boshlang‘ich sozlash», подзаголовком о четырёх шагах, строкой «n / 4 qadam tayyor», списком шагов, офлайн-пояснением (показывается при отсутствии сети), пояснением о безопасности демо и кнопкой «Yopish». Внутреннее состояние `running: SetupStepId | null` блокирует повторные нажатия и показывает «Yuklanmoqda…» на активном шаге.

Подписи — узбекской латиницей: «Xodimlar», «Materiallar», «Operatsiyalar», «Birinchi buyurtma», «Tayyor», «Qo‘lda kiritish», «Demodan olish», «Yopish».

### 3.3 `src/App.tsx`

- После успешного `bootstrapCompany`: `setModal({ type: 'setup' })`.
- `runSetupDemo(step)` — цикл «построить команду → выполнить → повторить» с локальными `latest`/`nextActor`, как в `runAll`; ограничение 24 итераций; в облаке перед стартом требуется сеть; успех и ошибки выводятся обычным уведомлением.

- Модалка `modal?.type === 'setup'` и добавление `'setup'` в список исключений общего `Dialog`.

### 4.5 Идемпотентность и совместимость

- Наличие проверяется по нормализованному имени; повторный запуск шага сразу возвращает `null` и ничего не пишет.
- Существующие записи не перезаписываются: демо только добавляет недостающее.
- Если имя занято несовместимой записью (например, неактивная операция «Jilolash»), домен вернёт ошибку «Name already exists»; уже созданные записи сохранятся, повторный запуск продолжит с места остановки, а конфликт владелец решает вручную.

## 5. Ошибки и ограничения

- **Облако + офлайн: демо запрещено.** Офлайн-очередь генерирует клиентские ID, и последующие команды, ссылающиеся на ранее созданные записи, не совпадут с серверными ID. Кнопки «Demodan olish» отключаются, показывается пояснение.
- **Частичное выполнение.** При ошибке цикл останавливается, состояние остаётся на последнем успешном результате, показывается текст ошибки. Повторный запуск безопасен благодаря идемпотентности.
- **Обрыв сети посреди загрузки.** Последующие команды могут попасть в существующую офлайн-очередь; мастер это не обходит и не маскирует — действуют обычные правила синхронизации и уведомления.
- **Демо не удаляет и не сбрасывает** данные компании.
- **Мастер необязателен:** закрывается на любом шаге; прогресс сохраняется в данных, а не в интерфейсе.
- **Только облако и администратор** видят точку повторного запуска; демо-режим приложения мастер не показывает.

### Регрессии и границы

- Полный `npm test`, `npx tsc -b --pretty false`, `npm run build` — зелёные.
- Браузерный smoke демо-режима: приложение открывается, разделы и Sozlamalar не сломаны. Облачный путь мастера (автоокрытие после создания компании и демо-загрузка) требует реальной компании в живой базе и проверяется только по отдельному разрешению владельца; до этого он покрыт component-тестами и PGlite-зондом.
- Публикация (`npm run deploy`) и живые SQL-изменения — только по отдельному разрешению.
