# PWA + Native-Feel UX — спецификация (Часть 1)

**Дата:** 2026-11-09
**Статус:** одобрен дизайн, ожидает ревью владельца
**Подход:** Вариант A — аддитивный PWA-слой поверх существующего интерфейса.

## Цель

Сделать Aliya ERP устанавливаемым PWA-приложением с «нативным» ощущением на телефоне:
установка на главный экран, офлайн-работа, тактильный отклик, плавные анимации,
скелетоны загрузки и свайп-действия в списках. Без изменения доменной логики.

## Ограничения (обязательные)

- Не Git-репозиторий: без веток и коммитов; каждый шаг завершается проверкой.
- Без субагентов: реализация inline, TDD (RED → GREEN).
- UI — узбекская латиница, суммы в UZS; отчёты владельцу — на русском.
- Деплой (`npm run deploy`) и любые удалённые изменения — только по отдельному разрешению владельца.
- Тесты выполняются в node-окружении Vitest (без jsdom).
- `prefers-reduced-motion` отключает анимации.

## Исходное состояние (уже есть)

- `sw.js` генерируется Vite-плагином `offlineShell` (в vite.config.ts): кэш ассетов, network-first для навигации с офлайн-фолбэком. Регистрация в `src/main.tsx` только в PROD.
- Нижняя мобильная навигация `.mobile-nav` / `.mobile-nav-item` (safe-area-inset-bottom, бейджи).
- Офлайн-очередь команд (pending + retryPending) и индикатор синхронизации в App.tsx.
- `viewport-fit=cover` и `theme-color` в index.html.

## Решения по продукту (согласованы с владельцем)

- Устройства: Android и iPhone → вибрация и push-возможности трактуются как progressive enhancement.
- Push-уведомления: **не делаем** в Части 1 (вернёмся отдельным шагом).
- Объём: полный пакет — manifest + установка, офлайн, вибрация, микроанимации, скелетоны, свайпы.
- С телефона используются все сценарии (цех, продажи, касса, отчёты) → настройка универсальная.

Модифицируемые файлы (точечные вставки, без домена):

## Компоненты

### manifest.json

- `name`: "Aliya", `short_name`: "Aliya"
- `start_url`: "/", `display`: "standalone", `orientation`: "any"
- `lang`: "uz", `dir`: "ltr"
- `theme_color`: "#172e2a", `background_color`: "#fdfefb"
- `icons`: 192×192 (any) и 512×512 (any, maskable необязательно).

### haptics.ts

Публичный API: `haptic(kind: 'tap' | 'success' | 'warning'): void`.

Паттерны (мс, `navigator.vibrate`):
- tap: `[15]`
- success: `[20, 30, 20]`
- warning: `[40, 40, 40]`

Правила:
- Функция принимает подменяемую `vibrate` (для тестов) с дефолтом на `navigator.vibrate`.
- Нет `navigator.vibrate` (iPhone, ПК) → no-op.
- `prefers-reduced-motion: reduce` → no-op.
- Вызовы только из общего обработчика команд `run()`: tap при старте сохранения, success при успехе, warning при ошибке. Больше нигде (не жужжать зря).

### swipe.ts

- Чистая функция `swipeDecision(deltaX: number, threshold = 60): 'none' | 'reveal'`.
- Обработчик `attachSwipe(element, { onReveal, onClose })` на pointer-событиях (pointerdown/move/up/cancel).
- Только touch-указатели (`pointerType === 'touch'`) — на десктопе свайп не мешает горизонтальной прокрутке таблиц.
- Порог 60px; при отпускании — пружинная анимация в состояние «открыто»/«закрыто».
- `prefers-reduced-motion` → без пружины, мгновенный сдвиг.

### Skeleton.tsx

- `<Skeleton rows={n} />` — n блоков-строк; shimmer-анимация.
- Используется вместо текста «Yuklanmoqda...» на экранах заказов, клиентов, кассы, отчётов, когда `busy && нет данных`.

### pwa.ts (установка)

- Перехват `beforeinstallprompt` → сохранить событие, показать баннер «Ilovani o'rnatish».
- Клик → `prompt()`; `appinstalled` → скрыть баннер.
- На iOS (`beforeinstallprompt` отсутствует) → баннер-подсказка: «Safari → Ulashish → Bosh ekranga qo'shish».
- Баннер не показываем, если событие не пришло или приложение уже в standalone.

## Data flow

1. **Установка:** событие → состояние `installEvent` → баннер → prompt → appinstalled → скрыть.
2. **Вибрация:** `run(command)` → `haptic('tap')` → `apply` → успех: `haptic('success')`, ошибка: `haptic('warning')`. Без состояния, fire-and-forget.
3. **Свайп:** pointer-события → translateX строки → порог → кнопки действий → существующая команда через `run()`.
4. **Скелетоны:** флаг `busy` уже есть в App → передаётся панелям → рендер Skeleton.

## Действия свайпа (безопасные)

- Заказы: свайп влево → «Tahrirlash» и «Arxiv».
- Касса: свайп влево → «Tahrirlash».
- Удаление НЕ выносится в свайп — остаётся внутри карточки с подтверждением.

## Обработка ошибок и края

- Нет вибрации (iPhone/ПК) → no-op, без ошибок.
- Нет beforeinstallprompt (уже установлено / не поддерживается) → баннер скрыт.
- `prefers-reduced-motion` → отключить shimmer и пружину.
- iOS standalone → apple-meta теги; safe-area уже обрабатывается.
- Обновление SW: кэш-версия меняется автоматически; добавить тост «Yangi versiya» с кнопкой перезагрузки (скрыть при `serviceWorker` недоступен).

## Тестирование

- **Unit (node, vitest):**
  - manifest.json парсится и содержит обязательные поля (name, display: standalone, иконки, theme_color).
  - `haptic` возвращает выбранный паттерн через подменяемую `vibrate`; no-op при её отсутствии и при reduced-motion.
  - `swipeDecision` для deltaX ≥/< порога.
  - `Skeleton` отдаёт корректное число блоков (конфиг-функция).
- **CSS-регрессии:** через существующий парсер правил (как в mobileStyle.ts) — проверка наличия shimmer, свайп-кнопок, reduced-motion блока.
- **Браузер:** 1280 / 759 / 390 / 320; баннер установки, свайп на touch, офлайн-перезагрузка в preview-сборке (`npm run build && npm run preview`).
- **Без деплоя** до отдельного разрешения владельца.

## Критерии готовности

- Приложение ставится на главный экран Android и iPhone (через инструкцию Safari).
- Офлайн-перезагрузка открывает приложение; офлайн-команды попадают в очередь.
- Вибрация ощущается на Android при сохранении/успехе/ошибке; на iPhone тихо.
- Списки показывают скелетоны при загрузке и поддерживают свайп на телефоне.
- Все unit-тесты и CSS-регрессии зелёные; `npm run build` проходит.
