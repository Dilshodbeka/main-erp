# Покраска/шлифовка + склад + экономика — спецификация (Часть 2)

**Дата:** 2026-11-09
**Статус:** одобрен дизайн (подход A), ожидает ревью владельца
**Подход:** A — нормы на операцию + производный расчёт, без отдельного модуля покраски.

## Цель

Добавить в Aliya ERP учёт покрасочных и шлифовальных работ как операций с
нормированием материалов на 1 м², авторасчёт себестоимости (материалы +
сдельная ЗП маляра/шлифовщика + износ абразивов) и расширение склада
категорией ЛКМ/химия. Без новых таблиц и без изменения существующей
логики выдачи материалов и расчёта себестоимости для серийных заказов.

## Ограничения (обязательные)

- Не Git-репозиторий: без веток и коммитов; каждый шаг завершается проверкой.
- Без субагентов: реализация inline, TDD (RED → GREEN).
- UI — узбекская латиница, суммы в UZS; отчёты владельцу — на русском.
- Деплой (`npm run deploy`) и любые удалённые изменения — только по отдельному разрешению владельца.
- Тесты выполняются в node-окружении Vitest (без jsdom); UI-тесты — через рендер-функции (как в существующих `*-ui.test.tsx`).
- Не менять поведение существующих заказов без норм: нормы аддитивны, дефолт — пустой массив.

## Исходное состояние (уже есть)

- `Item.kind: 'material' | 'blank' | 'finished'` — три ступени склада уже в модели.
- `Item.unit: string` — свободная строка: «litr», «kg», «dona», «m» уже работают.
- `Item.category: string | null` — код `XX.XX`; дерево категорий в `src/warehouse.ts` (`warehouseGroups`): группы 01–05 и 07 «Sarf materiallari» (включая `07.03 Abrazivlar`).
- `Operation.unit: OperationUnit` включает `'squareMeter'`; `workerRate` (ставка) и `salePrice` уже есть.
- `MaterialLine { qty, estimatedCost, issued, actualCost }` — плановая и фактическая стоимость уже есть.
- `RouteLine { operationId, planned, completed }` — у операции `squareMeter` это м².
- `estimatedCost(order)` = Σ материалов (qty × estimatedCost) + Σ маршрута (planned × rate) + overhead.
- `actualCost(state, order)` = Σ выданных материалов (issued) + принятая ЗП + принятый аутсорс.
- Списание: `order.update` (ревизия материалов) правит количество; `order.issue` выдаёт по средней себестоимости (`item.cost`) и создаёт движение склада.

## Решения по продукту (согласованы с владельцем)

1. **Площадь** = объём операции в м²: `RouteLine.planned/completed` у операции `squareMeter`.
2. **Нормы привязаны к операции**: `Operation.norms` — список `{ itemId, qtyPerM2 }`.
3. **Списание — по факту, вручную**: норма — это стартовая смета/подсказка; работник правит фактическое количество перед выдачей (через существующую ревизию материалов).
4. **Износ абразивов** = обычная норма на операции шлифовки (абразивы — материалы категории `07.03`); отдельного механизма износа не делаем.
5. **Склад**: добавляется группа `06 «Bo‘yoq va kimyo»` (ЛКМ/химия). Группа `07 «Sarf materiallari»` остаётся как есть — абразивы уже в `07.03`. (В roadmap Часть 2 называлась «07 Абразивы», но код 07 уже занят расходниками; абразивы живут в `07.03`.)
6. **Себестоимость не хранится** — считается производно; исторические снимки (подход B) — отдельным шагом, сейчас YAGNI.

## Архитектура

### Типы (`src/types.ts`)

- Новый интерфейс:
  ```ts
  export interface OperationNorm { itemId: string; qtyPerM2: number }
  ```
- `Operation` получает поле `norms: OperationNorm[]`.
- Команды `operation.create` и `operation.update` получают необязательное поле `norms?: OperationNorm[]` (дефолт `[]` в домене).

### Домен (`src/domain.ts`)

- **Валидация** в `operationValues`: `norms` (дефолт `[]`) — уникальные `itemId`; каждый item существует и `customerId === null`; `qtyPerM2 = quantity(...)` > 0.
- **Чистые функции расчёта** (для UI-разбивки и тестов):
  - `areaMaterialCost(norms, area, getCost)` = `Σ round(qtyPerM2 × area × getCost(itemId))`
  - `areaLaborCost(rate, area)` = `round(rate × area)`
- **Слияние норм в материалы заказа**: helper `normMaterialLines(state, route, lineId)` возвращает `MaterialLine[]` для задач с операцией `squareMeter` и непустыми нормами: `qty = qtyPerM2 × task.planned`, `estimatedCost = item.cost`, `issued: false`, `actualCost: 0`. Применяется **только при создании заказа** (путь `order.create`, не серийный) — как стартовая смета. Совпадение `itemId` с уже добавленными материалами суммируется; на ревизиях (`order.update`) нормы не пересчитываются — работник владеет фактическим количеством.
- **`estimatedCost` и `actualCost` не меняются**: после слияния краска/абразивы — это обычные `MaterialLine`, их плановая и фактическая стоимость уже входят в существующие формулы (материалы → `qty × estimatedCost`; факт → `issued × actualCost`; ЗП маляра → `route.planned × rate` / принятая payroll).

### Склад (`src/warehouse.ts`)

- В `warehouseGroups` добавляется группа:
  ```ts
  {
    code: '06', name: 'Bo‘yoq va kimyo', children: [
      { code: '06.01', name: 'Bo‘yoq' },
      { code: '06.02', name: 'Lak' },
      { code: '06.03', name: 'Grunt' },
      { code: '06.04', name: 'Qotiruvchi' },
      { code: '06.05', name: 'Erituvchi' },
      { code: '06.06', name: 'Shpaklyovka' },
    ],
  },
  ```
- Единицы (`litr`, `kg`) задаются через свободное `Item.unit` — без изменений валидации.
- Группировка по ступеням (сырьё/заготовки/готовая) уже есть через `Item.kind` (`finishedStock` и т.д.); отдельный фильтр добавляем только если владелец попросит.

### UI

- **Редактор операции** (`src/components/QuickEditors.tsx`, `OperationRateEditor`): для операции с `unit === 'squareMeter'` — секция норм: строки «материал + расход на 1 м²» (добавить/удалить). Сохраняется через `operation.update` с `norms`.
- **Редактор заказа** (`src/order-editor.tsx` и связанные): материалы норм появляются в смете как обычные строки материалов (уже рендерятся), с подписью-подсказкой о норме; работник правит количество вручную.
- **Разбивка себестоимости**: на вкладке производства у операции `squareMeter` показывается плановая смета материалов (норма × площадь × средняя себестоимость) и сдельная ЗП (ставка × м²) — через `areaMaterialCost` / `areaLaborCost`.

### Демо-данные (`src/seed.ts`)

- Материалы: краска (06.01), лак (06.02), отвердитель (06.04), растворитель (06.05), абразивные круги (07.03) — единицы «litr»/«dona».
- Операции: `Bo‘yash` и `Jilolash` с `unit: 'squareMeter'` и нормами на 1 м² (краска + отвердитель; абразивы — на шлифовке).
- Демо-заказ на покраску, чтобы проверить смету и списание в браузере.

## Data flow

1. **Настройка норм:** владелец задаёт операцию покраски (`squareMeter`) и её нормы (материал + расход/м²).
2. **Создание заказа:** в маршруте задача покраски с площадью N м² → `normMaterialLines` добавляет в материалы строки `норма × N` (подсказка-смета).
3. **Смета:** `estimatedCost(order)` автоматически включает материалы покраски и ЗП маляра.
4. **Факт:** работник правит количество материалов (ревизия) → `order.issue` выдаёт по средней себестоимости → `actualCost(order)` включает фактический расход и принятую ЗП.

## Обработка ошибок и края

- Нормы без операций `squareMeter` не порождают материалы (слияние только для задач с `unit === 'squareMeter'`).
- Норма ссылается на материал клиента (`customerId !== null`) → отклоняется при сохранении операции.
- Не хватает краски на складе при выдаче → существующая проверка `order.issue` «Insufficient stock» (блокировка при дефиците — базис для Части 4).
- Удаление материала из сметы при ревизии: строка нормы вернётся при следующем создании заказа, но не при ревизии (ревизия норм не пересчитывает). Чтобы не списывать краску — снять норму с операции или оставить количество 0.
- Серийные заказы: нормы в смету серии не сливаются (у серии материалы из рецепта); смета покраски в серии — отдельным шагом, сейчас вне скоупа.

## Тестирование

- **Unit (node, vitest):**
  - `operation.create/update` принимает `norms`, отклоняет дубли `itemId`, неизвестный item, материал клиента, `qtyPerM2 ≤ 0`.
  - `areaMaterialCost` / `areaLaborCost` считают корректно (включая округление).
  - `normMaterialLines` порождает строки только для `squareMeter`-задач, суммирует совпадения `itemId`, ставит `estimatedCost = item.cost`.
  - Создание несерийного заказа с покрасочной задачей добавляет материалы нормы; `estimatedCost` включает их.
  - Серийный заказ не получает материалы норм (регрессия).
- **UI-тесты (render-функции):** редактор операции показывает/сохраняет нормы; разбивка себестоимости в редакторе заказа.
- **Браузер:** демо-режим — создать заказ на покраску, увидеть смету, изменить фактический расход, выдать материалы, проверить `actualCost`.
- **Без деплоя** до отдельного разрешения владельца.

## Критерии готовности

- Операция покраски/шлифовки хранит нормы на 1 м² и показывается в смете заказа.
- Себестоимость (материалы + ЗП + абразивы) считается автоматически для заказов с покрасочными операциями.
- Фактическое списание материалов работает через существующую ревизию и выдачу.
- Склад показывает категорию 06 (ЛКМ/химия); абразивы — в 07.03.
- Все unit- и UI-тесты зелёные; `npx tsc -b --pretty false` и `npm run build` проходят; демо-сценарий проверен в браузере.
