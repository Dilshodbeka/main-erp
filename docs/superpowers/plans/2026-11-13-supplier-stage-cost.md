# Supplier Stage Cost (Pudratchi xizmati) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A supplier (pudratchi) production stage is priced by one manual fixed sum («Pudratchi summasi») instead of `rate × qty`; the sum drives plan cost, supplier debt, actual cost, invoice cost and the payment prefill, while employee stages keep `rate × qty`.

**Architecture:** Add optional `supplierCost` to `RouteLine`/`OrderRouteInput`; three exported domain helpers (`supplierStagePlan`, `supplierStageActual`, `supplierStagePriced`) become the single source of truth; legacy supplier stages with `rate > 0` and `supplierCost = 0` keep working through the fallback `planned|completed × rate`. The order editor renders a number input instead of the rate/amount pair for supplier rows, acceptance requires a positive sum, and PostgreSQL mirrors every rule (`supplier_cost` column, rewritten route functions, acceptance guard, snapshot).

**Tech Stack:** React 19 + TypeScript strict, Vite 6, Vitest (SSR markup tests only), Supabase/PostgreSQL (`erp_execute`, `erp_snapshot`), PGlite probes.

**Spec:** `docs/superpowers/specs/2026-11-13-supplier-stage-cost-design.md`

## Global Constraints

- The working folder is **NOT a Git repository**: never run git, never commit. Verification commands replace commits: `npx vitest run <files>`, `npx tsc -b`, `npm run build`.
- **No deploy, no live SQL, no remote changes** without separate explicit authorization naming Worker `erp-tizim`.
- UI copy stays Uzbek Latin with UZS; owner-facing reports stay Russian.
- Component tests are SSR-only: `renderToStaticMarkup(createElement(...))`. `fireEvent`, `userEvent` and jsdom are forbidden.
- Supplier money is **never** `rate × qty` when `supplierCost > 0`. Legacy fallback: `completed × rate` (actual) and `planned × rate` (plan) when `supplierCost = 0`.
- `supplierCost` is admin-only in the snapshot; workers receive `0`.
- Migration files are generated by script from `supabase/schema.sql`, never hand-edited. The probe applies schema + migration twice (idempotency).
- `formatMoney`/`money` output includes the `so‘m` suffix — assert labels and markers, not whole formatted strings.
- Do not print company data, backups or secrets to chat.

export function supplierStagePlan(task: RouteLine): number {
  if (task.executorKind !== 'supplier') return 0;
  return (task.supplierCost ?? 0) > 0 ? round(task.supplierCost!) : round(task.planned * task.rate);
}

export function supplierStageActual(task: RouteLine): number {
  if (task.executorKind !== 'supplier' || task.status !== 'completed') return 0;
  return (task.supplierCost ?? 0) > 0 ? round(task.supplierCost!) : round(task.completed * task.rate);
}

export function supplierStagePriced(task: RouteLine): boolean {
  return task.executorKind === 'supplier' && ((task.supplierCost ?? 0) > 0 || task.rate > 0);
}

export function stagePlanCost(task: RouteLine): number {
  return task.executorKind === 'supplier' ? supplierStagePlan(task) : round(task.planned * task.rate);
}
